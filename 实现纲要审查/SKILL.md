# 实现纲要审查

在 实现纲要 技能每步 AskUserQuestion **之前**由主 AI 调用。先用 Playwright 浏览器打开 HTML 验证可正常运行，再读取 HTML 和 MD 两个文件逐项对比。

**你是内部工具——审查结果只返回给调用你的主 AI，不呈现给用户。不写总结，不写建议，不跟用户说话。**

**HARD GATE:** FAIL → 主 AI 必须修复后重新审查，禁止 AskUserQuestion。

## 输入

主 AI 通过 Skill 工具的 args 参数传入 JSON 字符串：

```json
{"html路径": "实现纲要-{项目}.html", "md路径": "实现纲要-{项目}.md", "步骤": 1/2/3}
```

审查技能解析 JSON 后**先执行浏览器验证，再读取两个文件逐项对比**。

## 第一步：Playwright 浏览器验证（强制）

在比对 HTML 与 MD 内容之前，必须先用 Playwright 启动无头浏览器打开 HTML 文件，验证引擎是否正常加载、节点是否正常渲染、有无 JS 报错。

### 验证脚本

在 Playwright 中以无头模式启动 Chromium，打开 `file://` 协议的 HTML 文件，等待 5~8 秒渲染完成，然后执行以下检查：

```javascript
await page.goto(htmlFileUrl, { timeout: 15000 });
await page.waitForTimeout(7000);

// 1. 收集所有 pageerror
// 2. 收集所有 console.error / console.warn
// 3. 检查关键全局变量是否存在
const result = await page.evaluate(() => ({
  hasG6: typeof window.G6 !== 'undefined',
  hasGraph: typeof 图 !== 'undefined',
  hasApi: typeof window.api !== 'undefined',
  hasDataWarehouse: typeof 数据仓库 !== 'undefined',
  nodeCount: typeof 数据仓库 !== 'undefined' ? 数据仓库.节点.size : 0,
  edgeCount: typeof 数据仓库 !== 'undefined' ? Array.from(数据仓库.边.values()).reduce((s, e) => s + e.length, 0) : 0,
  themeValues: typeof 主题 !== 'undefined' ? Object.keys(主题) : null,
}));
```

### 通过条件

全部满足以下项才算 PASS：

| 检查项 | 条件 |
|--------|------|
| 无浏览器报错 | `pageerror` 列表为空 |
| G6 已加载 | `result.hasG6 === true` |
| 图实例存在 | `result.hasGraph === true` |
| api 可用 | `result.hasApi === true` |
| 数据仓库有节点 | `result.nodeCount > 0` |
| 主题色正常 | `result.themeValues` 非空，且关键值（节点填充/节点文字/强调色）不是空字符串 |

### 错误上报格式

浏览器验证失败时，**FAIL 报告的第一部分必须包含浏览器错误**，格式如下：

```
[浏览器] pageerror: <错误消息>
[浏览器] console.error: <控制台错误内容>
[浏览器] 状态: hasG6=false hasGraph=false nodeCount=0
```

浏览器验证 FAIL 时，**不需要继续执行后续的内容对比**，直接输出 FAIL 报告并终止。

## 第二步：内容对齐审查

**仅在浏览器验证 PASS 后**才执行以下步骤。读取 HTML 和 MD 两个文件，逐项对比。

### 1. 类型代理数量对齐
- 从 HTML 搜索所有 `api.添加类({` `api.添加接口({` `api.添加结构体({` `api.添加枚举({` `api.添加函数({` `api.添加变量({` 调用，提取 名称 + 类型
- 从 MD 搜索类型表格/清单中的所有类型名
- 按类别分组：类/接口/结构体/枚举/函数/变量/成员函数/成员变量
- 对比差异

### 2. 关系边数量对齐
- 从 HTML 搜索所有 代理.拥有( 代理.继承( 代理.实现( 代理.符合约定( 代理.符合( 代理.调用( 代理.依赖( 代理.添加关系( 调用，按关系类型分组计数
- **注意：** .添加成员函数() 每个调用会自动创建一条从父类型到成员函数代理的「拥有」关系——统计「拥有」关系总数时必须：代理.拥有( 显式调用数 **+** .添加成员函数() 调用总数 **+** .添加变量() 调用总数。
- **注意：** 代理.符合约定() 内部有去重逻辑——统计符合约定关系数时按 (源代理, 约定类型) 去重后再计数。
- 从 MD 关系表及约定表计数
- 不允许有差异

### 3. 责任映射对齐
- HTML `api.设置责任映射(` 调用数 vs MD 责任映射表条目数
- 每个类型必须有映射（枚举节点豁免；约定类型节点也豁免）
- **内容抽查：** 随机抽 3 条，比对职责描述文字是否一致。容差：允许标点符号/空白字符差异；不允许语义差异。遇到 `\"` vs `"` 或模板字符串差异，人工判定，不自动报 FAIL。

### 4. 置信度对齐
- MD 标注的置信度必须与 HTML 置信度参数一致

### 5. 成员函数对齐（第二步/第三步审查，第一步跳过）
- HTML .添加成员函数( 调用总数 vs MD 接口规划表条目数
- 必须等于「拥有」关系中源代理为类型、目标代理为成员函数的关系数

### 5b. 成员变量对齐（第二步/第三步审查，第一步跳过）
- HTML .添加变量( 调用总数 vs MD 接口规划表条目数
- 必须等于「拥有」关系中源代理为类型、目标代理为成员变量的关系数

### 6. 枚举完整性（条件触发）
- **仅当** HTML 中存在 `api.添加枚举({` 调用时才触发
- HTML 中枚举代理的枚举值数组内容必须与 MD 枚举清单一致（逐项比对）
- MD 必须有独立枚举清单 + 枚举值列表
- 枚举代理必须有关联关系
- HTML 中无枚举代理 → 此项自动 PASS，不报告"缺少枚举"

### 7. 约定类型对齐
- HTML 中标记了 是约定类型: true 的代理，MD 中必须标注为约定类型
- 约定类型代理在 HTML 中通过 代理.符合约定( 绑定的，MD 中对应的普通类型必须在约定列或约定表中体现
- 符合约定关系的数量在 HTML 和 MD 间必须一致
- 如果当前步骤为第一步（无约束表），则检查 MD 中对应类型的描述是否提及约定的存在

### 8. 测试项对齐（第三步审查，前两步跳过）
- **仅当** 步骤参数为 3 时才触发
- 每个类型代理和自由函数代理是否都有测试项
- 测试项是否覆盖：正常流程、边界条件、异常场景
- 测试项数量是否合理（每类型至少 2 个）
- 步骤 1 或 2 时此项自动 PASS

### 9. 功能拆解对齐（第三步审查，前两步跳过）
- **仅当** 步骤参数为 3 时才触发
- 每个类型代理是否有 _功能拆解 属性数组
- 功能拆解是否基于职责字段合理拆分
- 测试项是否覆盖了功能拆解中的每个功能点
- 步骤 1 或 2 时此项自动 PASS

### 10. 分组对齐（条件触发）
- **仅当** HTML 中存在 `api.设置分组(` 调用时才触发
- 组名必须非空且有语义（禁止"组1"、"其他"）
- 每个组成员 id 必须是已存在的代理或已先创建的组
- **组嵌套顺序检查：** 组 A 引用 组::组B，则设置分组('组B', ...) 必须在设置分组('组A', ...) **之前**调用
- **调用时机检查：** 所有 设置分组 调用必须出现在所有代理创建和关系设置调用**之后**
- HTML 中无 设置分组 调用 → 此项自动 PASS

## 输出格式

**只输出以下格式，不要加任何额外文字、建议、总结：**

浏览器验证 PASS 且内容对齐通过时：
```
审查结果: PASS
代理: N (类:X 接口:Y 结构体:Z 枚举:W 函数:V 变量:U 成员函数:T 成员变量:S)
关系: N (拥有:X 继承:Y 实现:Z 符合约定:W 符合:V 调用:U 依赖:R)
责任映射: N
成员函数: N
成员变量: N
测试项: N
功能拆解: N
分组: N (如有)
```

浏览器验证 FAIL 时（内容对比跳过）：
```
审查结果: FAIL (浏览器验证失败, N项)
  [浏览器] pageerror: <错误消息>
  [浏览器] console.error: <错误消息>
  [浏览器] 状态: hasG6=<值> hasGraph=<值> nodeCount=<值>
```

浏览器 PASS 但内容对齐 FAIL 时：
```
审查结果: FAIL (N项)
  [浏览器] 通过
  [缺失代理] MD有HTML没有: [类型A, 类型B]
  [缺失代理] HTML有MD没有: [类型C]
  ...
```

## 判定

- PASS → 主 AI 可以 AskUserQuestion
- FAIL → 主 AI 将差异项翻译为 SendMessage 指令给子代理修复 HTML，同时自行修复 MD，然后重新调用你审查。循环到 PASS 为止。

## 禁止行为

- ❌ 向用户展示审查报告或总结
- ❌ 写"建议"或"推荐修复方案"——那是主 AI 的事
- ❌ 自动修改任何文件
- ❌ 审查 PASS 后写总结文字
- ❌ 浏览器验证 FAIL 时仍然继续执行内容对比
