## 错误处理

| 错误码 | 触发条件 | 子代理行为 |
|--------|---------|-----------|
| ERR:MARKER_MISSING | Grep 找不到 ↓↓↓ 或 ↑↑↑ 标记 | 回复父技能：ERROR: 工作数据区标记缺失，文件可能已损坏，停止修改 |
| ERR:代理_NOT_FOUND | 指令引用的代理 id 在数据中不存在 | 跳过该操作，将该代理标记为"待补建"。如果后续指令依赖被跳过的操作（如添加从该代理出发的关系），一并跳过并累积 WARN。回复父技能：WARN: 代理「{id}」不存在，已跳过 N 条相关指令，继续执行其余独立指令 |
| ERR:CASCADE_SKIP | 因前置 WARN 导致当前指令被跳过 | 累计计数，与 WARN 一并报告给父技能。父技能收到累计 WARN 后应检查是否需要先补建缺失代理再重试 |
| ERR:EDIT_FAILED | Edit 工具 old_string 匹配失败 | 重试 3 次（第 1 次精确匹配，第 2 次容忍缩进差异，第 3 次忽略多余空白），仍失败则回复：ERROR: 编辑失败 — {简述} |
| ERR:AGENT_UNRESPONSIVE | SendMessage 发出后 30 秒无任何回复 | 回复父技能：ERROR: 子代理无响应。父技能收到后：首次 → 重新 spawn 子代理（新会话），从最后成功指令之后继续；连续 2 次 → 告知用户具体问题并等待指示 |

父技能收到 ERROR 后：同一错误连续 2 次 → 告诉用户具体问题 → 等用户指示。父技能收到 WARN 后：检查警告内容——如果涉及缺失代理导致后续指令被跳过（含 ERR:CASCADE_SKIP），应先发送补建代理的指令，再重试被跳过的指令。普通 WARN（不阻塞后续）则记录即可，不打断流程。
