## 全局规则

以下规则适用于所有阶段，必须严格遵守：

| 规则 | 说明 |
|------|------|
| **先获取需求再开始** | 调用技能后第一件事是确认需求来源，没有需求文档或需求描述就询问用户 |
| **绝不修改模板文件** | 必须先将 `template.html` 和 `data.template.js` 拷贝到工作目录再操作，原始模板保持只读 |
| **每步必须审查** | 本步产出完成后，系统自动执行审查（浏览器验证 + 修改审查），审查 PASS 才能 AskUserQuestion |
| **每步必须用户确认** | 用户确认后才能进入下一步，不允许自动跳步 |
| **阶段分工明确** | 第一步不写成员/约束，第二步不写测试，各司其职 |
| **只使用公开 API** | 不直接操作内部数据结构，通过 API 进行所有操作 |
| **视觉表现不重要** | AI 只关注关系和结构的正确性，图的样式由引擎自动处理 |

## 核心目标

在第一步的类型骨架基础上，补充内部细节：
1. **接口分化**：穷尽式列出每个类型的成员函数、成员变量
2. **实现约定**：补全约束（参数约定、模板约定、实现注意事项）

这一步结束后，每个类型的对外接口和内部约束都清晰了。

---

## 做什么

### 子步骤 1：接口分化（先做）

- 穷尽式列出每个类型的成员函数
  - 包括构造函数、析构函数、转换函数
  - 标注每个成员函数的职责和对应需求
  - 有签名的标注签名提示
- 穷尽式列出每个类型的成员变量
  - 标注变量名和类型
  - 标注职责和对应需求
- 补充全局自由变量
  - 标注变量名、类型、职责
- 此时不写约束，不写约定

### 子步骤 2：实现约定（后做）

- 调用 `设置阶段(阶段.实现约定)` 切换引擎阶段
- 补全约束
  - 参数约定（参数满足什么条件时触发什么行为）
  - 模板约定（模板参数需要满足什么）
  - 实现注意事项（使用时需要注意什么）
- 约束引用到的函数/变量必须在子步骤 1 中已创建
- 引导用户补充约束（AI 先根据需求推断，再请用户确认）

---

## 不做什么

- 不用再创建类型节点（第一步已完成）
- 不创建新的类型关系（继承/拥有已在第一步完成）
- 不写测试（第三步的事）
- 不修改第一步已确定的类型结构（除非用户明确要求）

## 怎么想

### 引擎自动推断

第二阶段很多关系由引擎自动推断，不需要手动设置：

| 关系类型 | 第二阶段 | 怎么自动推断 |
|----------|---------|-------------|
| 拥有 | ❌ 由引擎自动推断 | 添加成员函数/成员变量时自动创建拥有关系 |
| 调用 | ❌ 由引擎自动推断 | 函数声明"用到的变量"时自动创建调用关系 |
| 依赖 | ❌ 由引擎自动推断 | 函数返回值/参数类型自动创建依赖关系 |
| 继承 | ✅ 可手动设置 | 类实现接口、子类继承父类 |
| 符合约定 | ✅ 可手动设置 | 类型遵守约定 |
| 符合 | ✅ 可手动设置 | 运行时条件检查 |

> 第一阶段设置的 `代理.添加关系(目标, 关系名)` 在第二阶段由引擎自动替换为具体方法调用。自定义关系名无法映射时会被标记为待确认。

### 成员函数识别

- 行为/操作 → 成员函数
- 生命周期操作 → 构造函数/析构函数
- 类型转换 → 转换函数
- 每个成员函数必须有明确的职责描述
- 每个成员函数对应到具体的需求条目

### 成员变量识别

- 类型内部的字段/属性 → 成员变量
- 简单类型（string/int/bool）的字段永远是成员变量，不要升级成独立类型
- 当描述一个类型的字段/属性时，优先使用成员变量声明，而非创建独立数据容器类型
- 添加成员变量时必须同时提供名称和类型（至少一个，最好都有）

### 自由变量识别

- 全局配置 → 自由变量
- 全局状态 → 自由变量
- 全局常量 → 自由变量
- 不属于任何类型的独立数据 → 自由变量

### 约束识别

- "如果...则..." → 约束
- "必须满足..." → 约束
- "注意：..." → 约束
- 约束必须有明确的条件和触发效果
- 约束引用的函数/变量必须已存在

### 用到的变量

- 函数内部引用的外部变量 → 通过 `.用到的变量()` 声明
- 声明后引擎自动建立调用关系
- 可以指定访问模式（读/写）

---

## 常见错误

- 在第二阶段手动调用 `代理.添加关系(目标, "拥有")` 设置已由引擎自动推断的关系 ❌
- 忘记先调用 `设置阶段(阶段.实现约定)` 就写约束
- 约束遗漏（每个类型至少一个约束）
- 添加变量时未同时提供名称和类型
- 成员函数没有对应需求条目
- 约束引用了不存在的函数/变量
- 一步到位直接写第三步的内容（测试规划等）
