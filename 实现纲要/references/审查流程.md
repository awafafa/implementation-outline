本文件在执行审查阶段时读取，用于理解系统自动审查的流程。

## 审查机制（系统自动执行）

审查由 `review-enforcer` 插件自动执行，主 AI 无需手动调用任何审查技能。插件在每次回合结束时自动执行以下两个阶段：

### 阶段 1：浏览器验证

用 Playwright 无头 Chromium 打开 HTML 文件（通过本地 HTTP 服务器 `http://127.0.0.1:18080/` 访问，HTML 自动加载同名 `.data.js`）。使用 HTTP 协议而非 `file:///` 是因为 `api.加载数据()` 使用同步 XHR 加载外部数据文件，`file://` 下会被浏览器 CORS 拦截。HTTP 服务器在审查后保留运行，用户可通过同一 URL 访问实现纲要。检查：

| 检查项 | 条件 | 说明 |
|--------|------|------|
| 无页面错误 | errors 列表为空 | 捕获 `pageerror` 事件（未捕获的 JS 异常） |
| 无加载数据失败 | console 消息中不含 `加载数据` | 引擎的 `加载数据` 用 `console.warn`（非 `throw`），不触发 pageerror，需单独捕获 |
| G6 已加载 | result.hasG6 为 true | |
| 图实例存在 | result.hasGraph 为 true | |
| api 可用 | result.hasApi 为 true | |
| 数据仓库有节点 | result.nodeCount 大于 0 | |
| 无悬空依赖 | result.danglingEdgeCount 为 0 | 遍历 `导出全景图().边`，检查每条边的目标是否存在于节点集合中。若 `加载数据` 缺失/失败/位置错误，`.依赖('外部项目.类型')` 会创建指向不存在节点的边 → FAIL |

浏览器验证对同一 HTML 只调用一次（`.data.js` 和 `.html` 映射到同一 HTML 时自动去重）。

### 阶段 2：修改审查（差异审查 + 相同部分审查）

仅在有备份文件时执行（即文件被修改过）。并行运行两个子代理：

- **差异审查**：对比 `.data.js` 的 `执行工作数据()` 函数体的 diff，检查变更内容是否在用户指令授权范围内
- **相同部分审查**：检查未变更部分是否存在应当变更但未变更、或应当删除但未删除的内容

### 审查结果处理（插件自动）

- **PASS：** 插件放行，主 AI 将产出呈现给用户
- **FAIL：** 插件自动注入修复指令（通过 `goals.create`），主 AI 修复后重新审查，循环直到 PASS
- **FAIL 状态下绝不允许将结果呈现给用户**
